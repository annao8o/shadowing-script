# Shadowing Script (쉐도잉 스크립트) — 설정 안내

외국어 대본을 멘트별로 듣고 따라 말하는 연습 사이트입니다. 세트마다 연습 언어를 정할 수 있어서, 인도네시아어 말고 다른 언어로 바뀌어도 그대로 쓸 수 있어요.
스크립트는 **공간**(반·모임처럼 나누는 방)별로 모여 있고, 누구나 공간을 골라 들어가요(참여 코드는 없어요). 로그인하지 않아도 전체 공개 스크립트를 보고 연습할 수 있고, 사이트 전용 **아이디·비밀번호**로 로그인하면(Claude 계정은 필요 없어요) 들어간 공간의 멤버가 되어 스크립트를 올리고 공유받을 수 있어요.
필요한 것: **Supabase 계정**(데이터 저장, 무료), **GitHub 계정**(사이트 호스팅, 무료). 처음 한 번 20분 정도 걸립니다.

주요 파일
- `index.html` — 사이트 자체
- `supabase/migrations/` — 데이터베이스 설정. GitHub 연동을 켜 두면 Supabase가 자동으로 실행해요
- `admin-settings.sql` — 관리자 키 정하기 (SQL Editor에서 직접 한 번 실행)
- `README.md` — 이 안내

---

## 1. Supabase 프로젝트 만들기

1. https://supabase.com 에서 가입하고 **New project**를 누릅니다.
2. 이름은 자유(예: `shadowing`), Region은 **Northeast Asia (Seoul)**, 데이터베이스 비밀번호는 아무거나 길게 정해 둡니다.
3. 프로젝트가 만들어질 때까지 1~2분 기다립니다.

## 2. 데이터베이스 설정 (GitHub 연동)

GitHub 저장소를 Supabase에 연결해 두면, `supabase/migrations/` 폴더에 새 파일이 `main`에 올라올 때마다 Supabase가 알아서 실행해요. 무료 플랜에서도 돼요.

1. Supabase 왼쪽 아래 **Project Settings → Integrations** → **GitHub Integration**에서 **Authorize GitHub**를 누르고, GitHub 화면에서 **Authorize Supabase**를 누릅니다.
2. 저장소 목록에서 이 사이트의 저장소(예: `shadowing-script`)를 고릅니다.
3. **Working directory**는 `.` 그대로 둡니다.
4. **Deploy to production**을 켜고, production branch는 `main`으로 둡니다.
   (**Automatic branching**은 Pro 플랜 기능이라 꺼 둬도 돼요.)
5. **Enable integration**을 누릅니다.
6. 연결한 뒤 `main`에 새 커밋이 올라오면 설정이 실행돼요. 몇 분 뒤 **Table Editor**에 `sets`, `accounts` 같은 표가 보이면 성공입니다.

> 이전 버전의 `setup.sql`을 이미 실행한 프로젝트에 연결해도 괜찮아요. 첫 설정 파일은 여러 번 실행해도 안전해서, 올린 데이터와 관리자 키가 그대로 유지돼요.
>
> GitHub 연동 없이 쓰고 싶으면: `supabase/migrations/` 안의 파일을 **이름 순서대로** 하나씩 열어 SQL Editor에 붙여 넣고 **Run** 하면 돼요.

### 관리자 키 (한 번만)

저장소는 누구나 볼 수 있어서, 관리자 키는 GitHub에 올리지 않고 Supabase에서 직접 정해요.
이걸 하기 전까지는 **관리자 모드가 잠겨 있어요.** (공간은 관리자만 만들 수 있어요.)

1. `admin-settings.sql` 내용을 복사해 Supabase **SQL Editor** 새 쿼리에 붙여 넣습니다. (파일 자체는 고치지 마세요.)
2. SQL Editor 안에서 `'여기에-관리자-키를-적으세요'`를 본인만 아는 긴 비밀번호로 바꿉니다.
   (공간을 만들고, 모든 세트를 고치고 지우고, 비밀번호를 잊은 사람의 비밀번호를 새로 정해 줄 수 있는 키)
3. **Run**. `Success. No rows returned`가 나오면 성공입니다.

> 관리자 키를 나중에 바꾸고 싶으면 이 과정을 다시 하면 됩니다. 데이터는 지워지지 않습니다.
> 회원가입에는 참여 코드가 필요 없어요.

## 3. 사이트에 Supabase 연결

1. Supabase 왼쪽 아래 **Project Settings** → **API** (또는 **API Keys**) 화면을 엽니다.
2. 두 값을 복사합니다.
   - **Project URL** (예: `https://abcdxyz.supabase.co`)
   - **anon public** 키 또는 **publishable** 키 (`eyJ...` 또는 `sb_publishable_...`)
   - ⚠️ `service_role` 키나 `secret` 키는 **절대** 넣지 마세요. 사이트 파일은 누구나 볼 수 있습니다.
3. `index.html`을 메모장으로 열고 `NASKAH_CONFIG` 부분의 두 값을 바꿔 저장합니다.

```js
window.NASKAH_CONFIG = {
  url: 'https://abcdxyz.supabase.co',
  key: 'eyJhbGciOi...'
};
```

## 4. GitHub Pages로 사이트 공개

1. GitHub 저장소의 **Settings → Pages** → Branch를 `main`, 폴더 `/ (root)`로 두고 **Save**.
2. 1~2분 뒤 같은 화면 위쪽에 주소가 나옵니다: `https://내아이디.github.io/저장소이름/`
   이 주소를 연습할 사람들에게 보내면 됩니다.

> 이후 `main`에 올라온 변경은 자동으로 반영돼요. 사이트(`index.html`)는 1~2분 뒤, 데이터베이스(`supabase/migrations/`)는 Supabase가 실행한 뒤 반영됩니다.

## 5. 처음 열었을 때: 공간 만들기

1. 사이트에서 **로그인** → **처음이에요 · 회원가입**으로 이름·아이디·비밀번호를 넣고 가입합니다.
2. 이름 옆의 **사람 모양 아이콘(내 정보)**에서 **관리자 키**(2단계에서 정한 키)를 넣고 **관리자 모드**를 누릅니다. (본인 기기에서만)
3. 맨 위 오른쪽의 **공간 버튼**을 눌러 **공간 관리 → + 새 공간**에서 공간 이름(예: `인도네시아어 1반`)을 정하고 저장합니다.
4. 함께할 사람들에게 **사이트 주소**를 알려 주세요. 공간 버튼에서 공간을 골라 들어가면 돼요.

**공간**
- 스크립트와 폴더는 모두 한 공간에 속해요. 공간 목록은 누구에게나 보이고, 코드 없이 골라서 들어가요.
- 맨 위 **공간 버튼**으로 공간을 오가요. 새로 만드는 스크립트·폴더는 지금 보는 공간에 들어가요.
- **로그인한 사람**은 공간을 고르면 그 공간의 **멤버**가 돼요. 멤버는 그 공간에 스크립트를 올리고, 같은 공간 멤버와 일부 공개로 주고받을 수 있어요.
- **로그인하지 않은 사람**은 전체 공개 스크립트와 폴더를 보고 연습만 할 수 있어요(올리기·고치기·백업은 못 해요).
- 공간 이름은 관리자 모드에서 공간 버튼 → **공간 관리 → 이름 바꾸기**로 바꿔요. 공간은 관리자만 만들 수 있어요.
- 이 기능을 넣기 전에 만든 스크립트·폴더와 가입한 사람들은 모두 **기본 공간**에 들어 있어요.

## 6. 세트 만들기: 언어와 공유 범위

새 대본을 추가할 때 두 가지를 고릅니다.

**메모 줄** — 대본에서 `#`으로 시작하는 줄은 음성 없는 메모로 멘트 사이에 보여요(번호가 붙지 않고, 음성을 나눌 때도 빠져요). 예: `# 여기서 잠깐 쉬기`. 이미 만든 세트에 메모만 더하면 고쳐 둔 멘트 구간은 그대로예요.

**연습할 언어** — 목록에 언어가 표시되고, 위쪽 언어 버튼으로 걸러 볼 수 있어요. 기계 음성도 그 언어 목소리로 읽어요.
- 한글 발음 자동 생성은 **인도네시아어·말레이어**만 돼요. 다른 언어는 대본에 `대사 | 한글 발음 | 한국어 뜻`처럼 직접 적은 발음만 보여요.

**공유 범위**
- **전체 공개**: 누구나 볼 수 있어요(로그인하지 않은 사람도 그 공간에 들어가면 보여요).
- **일부 공개**: `@아이디`나 이름으로 사람을 찾아 지정해요. 지정받은 사람 화면에 알림이 뜨고, **수락**을 누르면 그 사람 목록에 들어가요. 거절하면 들어가지 않아요.
- **비공개**: 나만 봐요.
- 만든 뒤에도 목록에서 세트 옆 **톱니바퀴(세트 설정)** 버튼으로 범위와 사람을 바꿀 수 있고, 누가 수락했는지도 보여요.
- 공유받은 사람은 세트 화면 아래 **내 목록에서 빼기**로 언제든 뺄 수 있어요.
- 알림은 사이트를 열 때, 다시 화면으로 돌아올 때, 열어 둔 동안 30초마다 확인해요. 브라우저 탭 제목에도 `(1)`처럼 알림 수가 표시돼요.

**정렬** — 목록 오른쪽 위의 메뉴로 최근 수정순·최근 추가순·오래된 순·제목순을 고를 수 있어요. 고른 순서는 그 기기에 기억돼요. 폴더는 늘 스크립트보다 위에 같은 순서로 나와요.

**세트 설정** — 목록에서 세트 오른쪽의 **톱니바퀴** 버튼으로 만들 때 정한 것을 모두 바꿀 수 있어요 (세트를 올린 사람과 관리자에게만 보여요).
- 제목, 연습할 언어, 공유 범위, 대본, 나누기 기준
- 공유 범위는 폴더 밖에 있는 세트에서 바꿔요 (폴더 안의 세트는 폴더의 공개 범위를 따라요). 관리자 모드에서는 다른 사람이 올린 세트의 공유 범위도 바꿀 수 있어요.
- 음성: 기계 음성으로 만든 세트에 나중에 녹음 파일을 넣거나, 녹음을 새 파일로 바꾸거나, 녹음 대신 기계 음성으로 바꿀 수 있어요.
- 녹음을 넣거나 대본을 고치면 멘트 구간을 자동으로 다시 나눠요. 대사가 그대로인 줄의 화자와 직접 고친 발음은 유지돼요.

**폴더** — 목록의 **+ 새 폴더**로 폴더를 만들고, 여러 스크립트를 모아 둘 수 있어요 (로그인한 사람만, 폴더 안에 폴더는 없어요).
- 폴더를 연 상태에서 **새 대본 추가**를 누르면 그 폴더에 바로 들어가요. 이미 있는 스크립트는 톱니바퀴(세트 설정)의 **폴더**에서 골라 옮겨요.
- **공개 범위는 폴더가 정해요.** 폴더 안의 스크립트는 각자의 공개 범위 대신 폴더의 범위(전체 공개·일부 공개·비공개)를 따라요.
- 일부 공개 폴더는 받는 사람에게 알림이 가고, 한 번 **수락**하면 그 폴더에 나중에 넣는 스크립트도 함께 보여요. 받은 사람은 폴더 안에서 **내 목록에서 빼기**로 뺄 수 있어요.
- 폴더의 이름과 공개 범위는 목록에서 폴더 옆 톱니바퀴로 바꿔요.
- **폴더 지우기**를 해도 안의 스크립트는 지워지지 않아요. 지금 보던 사람이 그대로 볼 수 있게, 폴더의 공개 범위를 이어받아 목록으로 나와요.
- 스크립트를 폴더 밖으로 빼면(폴더 없음) 그 스크립트의 원래 공개 범위로 돌아가요.

## 오프라인으로 보기 (인터넷 없이)

1. 휴대폰에서 사이트를 열고 **홈 화면에 추가**하세요. (아이폰 사파리: 공유 버튼 → 홈 화면에 추가 / 안드로이드 크롬: ⋮ → 홈 화면에 추가)
2. 인터넷이 될 때, 필요한 것만 골라 저장해요.
   - 스크립트: 스크립트를 열고 맨 아래 **오프라인 저장**
   - 폴더: 폴더에 들어가 위쪽 **폴더째 오프라인 저장**. 나중에 그 폴더에 넣는 스크립트도 인터넷에 연결될 때 자동으로 함께 저장돼요.
3. 저장한 것은 목록에 **오프라인** 표시가 붙어요. 인터넷이 없으면 저장한 것만 보이고, 듣기·따라 말하기 연습을 할 수 있어요.

- 재생했다고 저절로 저장되지는 않아요. 고른 것만 저장돼요. 필요 없으면 같은 자리의 **오프라인 저장 해제**로 지워요.
- 오프라인에서는 올리기·고치기·공유·구간 수정은 할 수 없어요. 인터넷이 다시 연결되면 저장한 스크립트도 최신 내용으로 바뀌어요.
- 기계 음성 세트는 기기 목소리를 써서, 오프라인에서 읽어 주는지는 기기에 따라 달라요(아이폰은 대부분 돼요).
- 아이폰은 홈 화면에 추가하지 않고 쓰면, 사파리가 오래 쓰지 않은 저장 데이터를 지울 수 있어요.

## 7. claude.ai 페이지의 데이터 옮기기

1. claude.ai의 기존 연습 페이지에서 **백업** → **녹음 파일도 포함** 체크 → **백업 파일 내려받기**.
2. 새 사이트에서 **백업** → **백업 불러오기** → 그 파일 선택.
   녹음까지 그대로 옮겨집니다. (녹음 없이 백업한 세트는 기계 음성 세트로 들어옵니다.)
   백업에서 불러온 세트는 전체 공개로 들어오고, 일부 공개였던 세트는 공유 대상이 백업에 없어서 비공개로 들어옵니다.

## 알아 둘 점

**로그인과 공간**
- 로그인하지 않으면 전체 공개 스크립트만 보여요. 나머지는 로그인해서 그 공간에 들어가(멤버가 되어) 봐요.
- 공간 안에서: 전체 공개 세트는 누구나, 일부 공개는 지정해서 수락한 멤버가, 비공개는 나만 봐요. 일부 공개로 지정할 사람도 같은 공간의 멤버 중에서 찾아요.

**로그인**
- 한 번 로그인하면 그 기기에서는 계속 로그인된 상태로 유지됩니다 (180일 동안 안 쓰면 다시 로그인).
- 다른 기기에서도 같은 아이디·비밀번호로 로그인하면 내 세트를 똑같이 고칠 수 있습니다.
- 비밀번호는 서버에 암호화(bcrypt)되어 저장되고, 관리자도 볼 수 없습니다.
- 비밀번호를 10번 틀리면 그 아이디는 10분 동안 잠깁니다.
- **비밀번호를 잊은 사람**이 있으면: 관리자 모드에서 **내 정보 → 다른 사람 비밀번호 새로 정해 주기**에 그 사람의 아이디와 새 비밀번호를 넣고, 그 비밀번호를 알려 주세요.
- 본인 비밀번호는 **내 정보 → 비밀번호 바꾸기**에서 바꿉니다. 바꾸면 다른 기기는 자동으로 로그아웃됩니다.

**녹음 파일 업로드**
- 녹음 파일 업로드는 기술적으로 로그인과 별개로 열려 있어서, 사이트 밖에서 파일만 올려 두는 것은 완전히 막지 못했습니다. 대본·세트는 로그인해야만 올릴 수 있습니다. 걱정되면 Supabase **Storage → audio**에서 가끔 확인하세요.

**Supabase 무료 플랜**
- 데이터베이스 500MB, 파일 저장 1GB(m4a 녹음 기준 수백 개), 월 데이터 전송 5GB.
- **일주일 동안 이용이 거의 없으면 프로젝트가 일시정지**됩니다. 일주일 전에 경고 메일이 오고, Supabase 대시보드에 들어가 **Resume**을 누르면 다시 켜집니다 (데이터는 그대로).
- 무료 플랜은 자동 백업이 없습니다. 사이트의 **백업(녹음 포함)**을 가끔 내려받아 보관하세요. (백업 버튼은 로그인해야 보여요.)

**영구 삭제한 세트의 녹음 파일**
- 영구 삭제해도 녹음 파일은 Storage에 남습니다(누구도 지울 권한이 없게 해 두었기 때문). 용량이 신경 쓰이면 Supabase **Storage → audio**에서 직접 지우세요.

**문제가 생기면**
- 사이트 위쪽에 “서버에 연결하지 못해…” 문구가 보이면: 3단계의 URL·키가 정확한지, Supabase 프로젝트가 일시정지 상태가 아닌지 확인하세요.
